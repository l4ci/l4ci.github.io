Capture, build and ship work with Claude Code or Codex, one item or many.

rota turns a to-do list into reviewed, merged work. You capture an item, your agent builds it in small commits, and /rota-ship reviews the branch and merges it. What the project learned is kept for the next session.

One agent, one item

You stay in the conversation. You need git and Claude Code or Codex, and nothing else.

  1. /rota-capture

    Write it down

    Turn a brain dump into backlog items or issues. Mixed input, one line or a page.

  2. /rota-work

    Build it

    Picks the next item, plans it, and builds it in small commits on its own branch.

  3. /rota-ship

    Review, then merge

    Reviews the branch, then opens a PR or merges. /rota-ship --undo rolls a cycle back.

Getting started walks the loop end to end, with what each rota setup question decides.

A round: several agents in parallel

When you have a few independent issues, a round runs them side by side. You stay available for product questions.

Orchestrator
One agent that picks the next issues, hands them out, answers workers' questions and merges. It asks you only for product decisions.
Workers
Agents that each take one issue in their own git worktree and terminal tab, build it and open a PR. They never merge.
Gate
The only merge path. It checks the PR is current and signed off, merges it, then runs your full test suite on the merged main. A red result stops the round until it's fixed.

Your first round sets it up step by step. You'll want gh or glab, and herdr or tmux.

Runs in your terminal

A round runs in your terminal, not in a cloud dashboard. Every worker gets its own tab, so you can watch any agent, or type into one, at any time.

  • herdr reports each agent's state directly (working, blocked, done), and rota waits on those events instead of polling.
  • tmux works too: rota reads the panes to tell what each worker is doing.
  • Neither? The round still runs, with workers as subagents of the orchestrator.

Several accounts, balanced

Long rounds run into usage limits. List your accounts and rota spreads the work and routes around limits.

  • New work goes to the Claude account with the most headroom and skips one that is cooling down.
  • When a worker hits a limit, its issue moves to a free slot on another account and continues from the pushed branch.
  • The orchestrator hands off and restarts under another account before it hits its own limit.

Problems this fixes

What goes wrongWhat rota does
Agents start building before the task is clear./rota-brainstorm and /rota-plan settle it first.
A session ends and the next one starts blind..rota/ and /rota-pause carry state across.
Parallel agents collide or merge red.Each gets a worktree, and the gate tests the merged main.
Lessons get lost./rota-learn and /rota-decide keep them where the next session reads them.

A memory that lives in the repo

Both ways of working share .rota/, committed next to your code, so a fresh session picks up where the last one stopped.

.rota/
├── KNOWLEDGE.md    what the project has learned
├── DECISIONS.md    the lines it must not cross
├── BACKLOG.md      items, or your GitHub/GitLab issues instead
├── MILESTONES.md   the bigger picture
└── handoff/        notes for the next session

The .rota/ folder lists every file.
