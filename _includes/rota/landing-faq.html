Frequently asked questions

All questions
Why use rota if my agent already runs tasks?

rota coordinates several agents across issues and accounts. It assigns isolated work, routes reviews and checks the combined code before merging. You stay in your agent session and make the product decisions. How it works

Which coding agents can I use?

Workers can run Claude Code, Codex or OpenCode. The orchestrator is also an agent session: Claude Code, Codex, OpenCode or Hermes. Harness support

What does rota cost?

rota is free and MIT licensed. You use your own agent plans and accounts. More workers use more quota; a round summary shows the cost per issue, worker and account. Costs and quota

Can a worker merge broken code?

Workers open PRs; the orchestrator merges through the gate. It checks the required reviews and runs your configured tests on the PR combined with current main. Passing tests only cover what those tests check. You can also require approval before each merge. Safeguards and limits

What happens when I hit a usage limit?

With multiple accounts configured, rota can move an issue to an available worker on another account. If none has capacity, it waits for the limit to reset. Usage limits and unattended rounds

Do I need GitHub?

No. Use a local backlog or issues from GitHub, GitLab, Jira, Linear or itsaplan. Remote PRs and merges need a configured forge; projects without a remote can merge locally. Backlog options

Do I need herdr or tmux?

Use one for separate worker sessions and multiple accounts. Without either, rota can use Claude subagents in separate worktrees, sharing the orchestrator's account and usage limit. Worker setup
